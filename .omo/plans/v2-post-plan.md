## 波次规划

### Wave 1 — Phase 1 立即补齐（高优先级）

#### T1.1: P1.1 放宽列数验证（merge-file/merge-sheet）

**目标**: 在原有合并模式中允许后传文件列数 ≥ 基准文件列数（smart-merge 已实现，旧模式未改）

**改动**:
- `validateHeaderConsistency`: 将 `baselineMaxCol !== currentMaxCol` 改为 `currentMaxCol < baselineMaxCol` 时拒绝，`currentMaxCol >= baselineMaxCol` 时通过
- 验证通过后进入 `performSheetDataMerge`, `sourceColIdx = maxColumns` 固定位置逻辑已存在（Bug-1 修复）
- 同时修改 `merge-bug1` 测试：将"2列+5列"测试从"断言跳过"改为"断言成功合并为5列"

**风险**: 极低。改动 2 行条件 + 1 个测试断言

**估算**: 0.5 天

**依赖**: 无

---

#### T1.2: P1.2 拆分保留底部行（footerRows）

**目标**: split-column 和 split-sheet 拆分时保留底部合计行

**改动**:
1. `split-column` 和 `split-sheet` 的 Step 3 面板增加 `footerRows` 数字输入框（默认 0）
2. 拆分逻辑改为：`dataStart = headerRows; dataEnd = totalRows - footerRows`
3. 每个拆分文件输出：表头 + 分组数据 + 底部N行（从原表底部复制）
4. 拆分文件底部行的合并单元格需正确处理
5. `footerRows > 可用数据行数` 时兜底

**风险**: 中。需处理合并单元格在底部行的场景。处理逻辑在 split-column 和 split-sheet 两处修改。

**估算**: 1 天

**依赖**: 无

---

### Wave 2 — Phase 2 智能匹配（中优先级）

#### T2.1: P2.1 列标题智能匹配（按名对齐）

**目标**: 解决列顺序不同时按列名对齐而非按索引对齐

**改动**:
1. 新增 `performSmartSheetDataMerge` 独立合并函数
   - 收集所有文件的唯一列名
   - 保持第一个文件的列顺序为基准
   - 按列名映射写入数据，缺失列留空
2. 与现有 `performSheetDataMerge` 并行保留
3. 在 `smart-merge` 模式A 中增加子选项：位置匹配 / 列名匹配

**风险**: 中。新函数需与现有格式保持兼容，来源列逻辑需对齐。

**估算**: 2 天

**依赖**: T1.1

---

#### T2.2: P2.2 合并模式选择器

**目标**: 在 `smart-merge` 面板增加三种合并策略的选择

**改动**:
1. smart-merge Step 3 增加单选：严格追加 / 智能追加(按位置) / 标题匹配(按列名)
2. 三种模式技术映射：
   - 严格 → `performSheetDataMerge` (原样)
   - 智能 → `performSheetDataMerge` 放宽验证 (同 T1.1)
   - 标题匹配 → `performSmartSheetDataMerge` (同 T2.1)
3. 仅 `merge-sheet` 模式显示，`merge-file` 不受影响

**风险**: 低。主要是 UI 组合已有功能。

**估算**: 0.5 天

**依赖**: T2.1

---

#### T2.3: P2.3 合并预览

**目标**: 在真正合并前给用户概览

**改动**:
1. Step 3 与 Step 4 之间新增预览步骤（或 Step 3 内嵌预览区）
2. 显示：文件数、总行数、总列数、列名列表
3. 检测潜在问题：列数不一致、表头不匹配、空数据
4. 同意后再进入 Step 4 处理

**风险**: 低。纯前端计算，不涉及 SheetJS 写入。

**估算**: 1 天

**依赖**: T2.2

---

### Wave 3 — Phase 3 汇总计算（可选，价值驱动）

#### T3.1: P3.1 合并计算

**目标**: 按指定列分组汇总（求和/平均/计数/最大/最小）

**改动**:
1. 新增独立处理模式或 merge-sheet 子选项
2. UI: 分组依据列多选 + 数值列多选 + 计算方法单选
3. 核心函数 `performSummaryMerge` 实现分组汇总
4. 支持保留表头行

**风险**: 中。分组 UI 交互复杂（多选列），需处理用户选错非数值列的场景。

**估算**: 2-3 天

**依赖**: 无（独立模式），若作为 merge-sheet 子选项则依赖 T2.2

---

#### T3.2: P3.2 按关键列匹配（JOIN）

**目标**: 两表按关键列匹配合并（类 SQL JOIN）

**改动**:
1. 新增独立处理模式
2. 左表上传 + 右表上传（各一个文件）
3. 左键列选择 + 右键列选择 + JOIN类型(inner/left/right)
4. 核心函数 `joinWorksheets` 实现

**风险**: 中。两表上传 UI 与现有单文件/多文件上传模式不同。

**估算**: 2 天

**依赖**: 无（独立模式）

---

#### T3.3: P3.3 合并后自动排序

**目标**: 结果按指定列排序

**改动**:
1. 在合并完成后、结果展示前增加排序步骤
2. UI: 列选择 + 升序/降序
3. 可作为合并模式的通用后处理步骤

**风险**: 低。纯数组排序，不涉及 SheetJS。

**估算**: 0.5 天

**依赖**: 可作为 Phase 2/3 任意模式的后处理

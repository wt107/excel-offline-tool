### 2.1 🔴 P0 — 严重问题（3 项）

#### BUG-HTML-1: HTML 结构错误 — `</body></html>` 出现在内容中间

**位置**: `excel.html` L9289-9296

```
L9280: })();           ← IIFE 闭包结束
L9281: </script>
L9282: <div id="dataPreviewModal" ...>   ← 弹窗开始
...
L9289: </body>         ← 过早关闭！
L9290: </html>         ← 过早关闭！

L9292: <div ...>       ← 弹窗内容仍在 HTML 外！
...
L9296: </div>          ← 弹窗结尾
```

**影响**: 
- `dataPreviewModal` 的后半部分（表格容器、提示文字）在 `</body>` 之后，属于无效 DOM
- 浏览器虽然会尝试解析（容错），但行为不可预测
- 数据预览功能可能部分失效或布局错乱
- 不符合 HTML5 规范

**修复**: 将 L9289-9290 移动到 L9296 之后

#### BUG-CODE-2: `style.display` 混用 — 121 处内联样式与 CSP-safe 类混用

**现状**: 
- 已有 CSP-safe 的 `csShow()`/`csHide()` 辅助函数（L2770-2793）
- 已有 `.cs-hidden`/`.cs-flex`/`.cs-block` CSS 类（L1028-1031）
- 但仍有 **121 处** 使用 `el.style.display = 'flex'/'none'/'block'`
- 分布在 loading 控制、结果面板切换、弹窗显示等多个关键路径

**影响**:
- 违反项目自身的 CSP 策略（`style-src 'self' 'unsafe-inline'`）
- 虽然 `'unsafe-inline'` 暂时允许，但这与设计文档中"CSP-safe"的目标矛盾
- 未来若收紧 CSP，这些地方会立即崩溃

**关键位置**:
- `performSmartMerge()` L6606-6609: `loading.style.display = 'flex'`
- `performSheetDataMerge()` L5272-5275: 同上
- `showSkippedSheetsInfo()` L9260: `el.style.display = 'block'`
- `closeDataPreview()` L9251: `modal.style.display = 'none'`
- `dataPreviewModal` L9282: 内联 `style="display:none..."`

---

#### BUG-CODE-3: 智能合并模式A — 后续文件数据仅以纯文本追加，丢失类型信息

**位置**: `performSmartMerge()` L6684-6700

```javascript
// 后续文件的数据行处理：
var val = c < rowArr.length ? rowArr[c] : '';
if (typeof val === 'number') {
    mergedWs[addr] = { t: 'n', v: val };    // 仅保留值，丢失格式
} else if (typeof val === 'boolean') {
    mergedWs[addr] = { t: 'b', v: val };
} else if (val !== undefined && val !== null) {
    mergedWs[addr] = { t: 's', v: String(val) };
}
```

**问题**:
- `sheet_to_json()` 返回的值已丢失原始单元格类型信息（日期变成数字、公式丢失）
- 第一个文件通过 `cloneWorksheet()` 保留格式，后续文件**全丢**
- 日期类型被转为数字序列号（如 `45678`），用户看到的是乱码而非日期
- 公式结果值丢失，仅保留当时的计算结果

**影响**: 模式A 在处理含日期/公式的文件时，数据严重失真。UI 已有警告但措辞不够明确。

### 2.2 🟠 P1 — 重要问题（9 项）

#### CODE-4: 全局变量过多（20+ 个可变全局状态）

```
currentMode, workbook, selectedSheets, splitColumn, generatedFiles,
originalFileName, zipBlob, selectedSheetForColumn, splitReport,
verticalKeyColumns, selectedVerticalColumns, uploadedFiles,
mergedFileBlob, mergedFileName, zipFileName, originalFileType,
isXlsFile, isProcessing, processingAbortController, failedFiles,
hasDownloaded, activeObjectURLs, pendingRevokeTimers,
lastMergeStatistics, lastSkippedSheets, splitSheetSearchKeyword,
workbookCache
```

**风险**: 状态耦合严重，任一变量意外修改都可导致功能异常。`resetTool()` 必须逐一清理，遗漏即出 bug。

**建议**: 将状态封装为 `AppState` 对象（已有骨架但未使用），`resetTool()` 只需 `Object.assign(AppState, defaultState)`。

---

#### CODE-5: 代码重复严重 — 拆分/合并逻辑重复实现

| 重复模式 | 出现次数 | 说明 |
|----------|---------|------|

| ZIP 打包 | 4 处 | split-sheet/split-rows/split-column-vertical 各自独立实现 |
| 来源列添加 | 3 处 | performSheetDataMerge/smart-merge模式A/模式B 各自实现 |
| 进度更新模式 | 6 处 | `progressBarFill.style.width = ...` 散落各处 |
| 单文件模式写入 | 3 处 | split-sheet/split-rows/split-column 各自实现 |

#### CODE-6: 缺少取消操作的完整支持

**现状**:

- 但**没有取消按钮 UI**，用户无法在处理中取消操作
- 处理大文件时，用户只能刷新页面

#### CODE-8: `escapeHtml()` 未在部分 innerHTML 场景使用

**已使用**: L9232 数据预览、L6579 去重列名

**未使用**: 
- `showMergeStatistics()` L9089-9106: `span.textContent = item` — **安全**（使用 textContent）

**结论**: 大部分已安全，但 `innerHTML = html` 在 L9246（数据预览表格）使用 `escapeHtml` 转义，安全。整体 XSS 风险低。

#### CODE-9: `AppState` 对象定义但未实际使用

**位置**: L2840-2853

#### CODE-10: `workbookCache` 在 `resetTool()` 中已清理但定义位置不明确

**位置**: `workbookCache.clear()` 在 L3036

`WorkbookCache` 类定义在自测附近，但作为全局缓存，其生命周期管理与页面状态不完全同步。多次 reset 后缓存清空，但同一文件重新上传时会重新解析，不存在问题。

## 九、结论

### 整体评价

**本工具在"离线、零安装、隐私保护"这一产品定位上做到了极致**，9 个功能模式覆盖了最常用的拆分/合并场景，其中"按名称归类合并"和"数据匹配（JOIN）"甚至超越了 WPS 和 Kutools 等商业产品。

### 核心风险

1. **HTML 结构错误**（BUG-HTML-1）是最紧急的修复项，虽然浏览器容错但行为不可预测
2. **智能合并模式A 的日期/公式丢失**是功能性 bug，影响数据可靠性，必须优先修复
3. **9296 行单文件**是最大的技术债，随着功能增加将越来越难维护

### 评分

| 维度 | 评分（5分制） | 说明 |
|------|:---:|------|
| 功能完整性 | ⭐⭐⭐⭐ | 9 模式覆盖主流场景，3 个超越竞品 |
| 代码质量 | ⭐⭐⭐ | 核心算法优秀，但单文件过大、状态管理混乱 |
| 数据正确性 | ⭐⭐⭐ | 大部分正确，模式A 日期/公式丢失是硬伤 |
| 用户体验 | ⭐⭐⭐ | 基础体验好，缺少取消/撤销/引导 |
| 安全性 | ⭐⭐⭐⭐ | XSS 防护好，CSP 待完善 |
| 可维护性 | ⭐⭐ | 9296 行单文件 + 20+ 全局变量 |
| 性能 | ⭐⭐⭐ | Time-Slicing 有效，但 XLSX.read 阻塞无解 |
| 测试覆盖 | ⭐⭐⭐⭐ | 60+ 自测 + 60 E2E，覆盖较好 |
| 竞品对比 | ⭐⭐⭐⭐⭐ | 零安装 + 跨平台 + 隐私 = 降维打击 |

**综合评分: 3.5 / 5** — 在产品定位上非常出色，但技术债和少数数据正确性问题需要优先解决。

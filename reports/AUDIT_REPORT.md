## 二、代码审核（开发者视角）

### 2.1 🔴 严重问题（P0）

| # | 问题 | 位置 | 说明 |
|---|------|------|------|
| C-01 | **`.style.display` 与 CSP-safe 策略不一致** | 全局 115 处 | 代码中有 `csShow/csHide` CSP-safe 函数，但 `generateSplitFiles`、`performMerge`、`performSmartMerge` 等核心函数仍直接使用 `loading.style.display = 'flex'` 等内联样式（约 30+ 处），与既定 CSP 策略矛盾。虽然当前 CSP `style-src 'self' 'unsafe-inline'` 允许，但设计意图是消除内联样式，当前为半完成状态 |
| C-02 | **`AppState` 定义在 `getEffectiveProcessingMode` 之后** | L1759 引用、L2832 定义 | `getEffectiveProcessingMode()` 使用 `typeof AppState !== 'undefined'` 做防御性检查，说明 `AppState` 定义在使用之后。这是 JS 变量提升（hoisting）的隐患——`var AppState` 被提升但值为 `undefined`，`typeof` 检查恰好绕过了这个问题，但逻辑依赖不清晰 |
| C-03 | **`AppState` 与全局变量双轨状态管理** | L1642-1664 + L2832-2845 | 状态分散在两处：① `let currentMode`、`let workbook` 等全局变量 ② `AppState.config` 对象。`processingMode` 既存在 `AppState.config.processingMode` 又有 DOM `input[name="processingMode"]`，三处数据可能不同步 |

### 2.2 🟠 重要问题（P1）

| # | 问题 | 位置 | 说明 |
|---|------|------|------|
| C-04 | **`var`/`let`/`const` 混用** | 全局 | 516 处 `var`、116 处 `let`、871 处 `const`。同一函数内混用 `var` 和 `let/const`，如 `generateSplitFiles` 中 `const loading` 和 `var sheetNamesArray`。设计文档标注"兼容 Win7 旧版 Chrome"，但 `let/const`、`Set`、`Map`、`async/await`、`class` 等已大量使用，`var` 兼容性理由已不成立 |
| C-05 | **`addEventListener` 无对应 `removeEventListener`** | 62 处绑定 / 1 处解绑 | 62 个事件监听器仅在 `DOMContentLoaded` 中绑定，但 `resetTool()` 不解绑任何监听器。用户多次使用工具时，事件处理函数不会被重复绑定（因为 DOM 不重建），但如果未来加入动态 DOM 重建，将导致事件泄漏 |
| C-06 | **`innerHTML` 使用风险** | 26 处 | 虽然大部分已改用 `createElement + textContent`，但仍有 `leftSelect.innerHTML = '<option value="">- 请先上传文件 -</option>'` 等硬编码 HTML 字符串。当前内容为静态文本无 XSS 风险，但模式不一致 |
| C-07 | **`cloneWorksheet` 与 `cloneWorksheetCustom` 功能重叠** | L3923 + L2207 | 两个函数做类似的事：`cloneWorksheet` 使用 `JSON.parse(JSON.stringify)`（完整但低效），`cloneWorksheetCustom` 使用逐字段拷贝（高效但略不完整）。调用者需自行判断使用哪个，缺少统一入口 |
| C-08 | **内存管理不完整** | L2986 `resetTool` | `resetTool()` 清理了 `workbook = null`、`generatedFiles = []`，但未清理 `workbookCache`（虽有 `.clear()` 方法），也未主动触发 GC。大文件处理后内存可能不会立即释放 |
| C-09 | **全局变量过多** | L1642-1664 | 约 20 个全局 `let` 变量（`currentMode`、`workbook`、`selectedSheets` 等），函数间通过全局变量隐式通信，增加了耦合度和调试难度 |
| C-10 | **`processWithYielding` 与手动 `setTimeout` 混用** | L1696 + 各处理函数 | 设计了 `processWithYielding` 通用时间片函数，但 `generateSplitFiles`、`performSheetDataMerge` 等仍使用 `await new Promise(resolve => setTimeout(resolve, UI_YIELD_DELAY_SMALL))` 手动切片。两种方式并存，`processWithYielding` 未被充分利用 |

### 2.3 🟡 改进建议（P2）

| # | 问题 | 位置 | 说明 |
|---|------|------|------|
| C-11 | **CSS 进度条宽度类不连续** | L1033-1041 | 仅定义了 `cs-progress-0/5/10/20/40/80/90/100`，但实际进度值可能是任意百分比。当前代码绕过 CSS 类直接使用 `progressBarFill.style.width = '35%'`，与 CSP-safe 设计理念矛盾 |
| C-12 | **缺少输入验证边界** | 各 `parseInt` 调用 | `parseInt(document.getElementById('splitRowsPerFile').value, 10) || 500` 使用 `||` 做 fallback，但 `0` 会被错误替换为 `500`。应使用 `if (isNaN(val) || val < 1) val = 500` |
| C-13 | **`console.log/warn/error` 残留** | 25 处 | 生产代码中保留调试日志。`DEBUG` 开关为 `false`，但非 DEBUG 条件下的 `console.error/warn` 仍会输出到控制台 |
| C-14 | **命名不一致** | 全局 | 变量命名混用驼峰和下划线：`srpPerFile`（缩写+驼峰）、`splitColumn`（驼峰）、`isXlsFile`（驼峰）、`srp_ws`（缩写+下划线）。部分函数名如 `srpRollbackFiles` 使用了无意义前缀 |
| C-15 | **错误消息语言不统一** | 全局 | 部分 `showToast` 用中文，部分用英文（`'操作已取消'` vs `'AbortError'`），对中文用户不友好 |
| C-16 | **SheetJS 版本锁定但无 SRI** | L11 | `<script src="lib/xlsx.full.min.js">` 无 integrity 校验。离线使用场景下风险较低，但如果文件被替换（如通过中间人），无法检测篡改 |
| C-17 | **`beforeunload` 事件粒度过粗** | L2863-2870 | 只要上传了文件就拦截关闭，即使用户已完成下载。应在下载完成后（`hasDownloaded = true`）不拦截，当前逻辑已部分实现但 `generatedFiles.length > 0` 的判断仍会误拦截 |

### 4.2 独特优势（差异化竞争力）

1. **零安装、跨平台**：浏览器打开即用，不依赖 Windows/Mac 特定环境
2. **完全离线、隐私安全**：数据不上传服务器，适合处理敏感数据
3. **按列竖向拆分**：WPS 原生不支持，Kutools 支持但需付费
4. **智能合并（按名称归类）**：WPS 原生不支持，独特功能
5. **数据匹配（JOIN）**：支持内/左/右连接，WPS 原生不支持
6. **ZIP 打包输出**：一键下载所有拆分结果
